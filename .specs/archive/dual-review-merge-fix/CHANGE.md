## Why（为什么做）

当用户通过 `gate_config` 对某阶段同时开启 L2（子 agent 盲审）和 L3（外部模型盲审）时，两者的审查结果写入同一份文件。由于当前写入方式为覆盖写（`>`），后执行的一方会覆盖先执行的一方的输出，导致其中一方的审查建议丢失，用户无法获得完整的双层审查反馈。

这对 `all` preset（6 个阶段全开 L2+L3）影响尤为严重——每个阶段都面临审查结果不完整的问题，预计每 pipeline run 丢失约 50% 的独立审查信号。

## What（做什么）

排查 L2 和 L3 审查流程中写文件的位置：L2 子 agent 使用 `Write` 工具全量覆写 `INDEPENDENT-REVIEW-<phase>.md`，当 L3 已通过 Stop hook 或 PreToolUse 产出 L3 段后，L2 的重写会销毁 L3 内容。L3 的 `>>` 追加逻辑（`l3-review.sh:174-198`：awk 剥离旧 L3 段 → `>>` 追加新段）已正确处理，保留不变。修复重点：① L3 不应在 L2 完成前写 `.done` ② L2 子 agent 应追加而非覆写 ③ `.done` 仅在双方均完成时写入。
