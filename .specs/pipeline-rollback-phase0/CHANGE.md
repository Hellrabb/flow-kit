# CHANGE: Pipeline 回退协议扩展到 0-3 规划阶段（智能回退方案 C）

- **Change ID**: pipeline-rollback-phase0
- **创建日期**: 2026-06-20
- **路径建议**: 完整（REQUIREMENT → DESIGN → TASK → DEV → TEST → REVIEW → INTEGRATION）
- **状态**: active

---

## Why（为什么做）

`goal-pipeline-phase0` change（2026-06-20）把 pipeline 起始阶段从 4 扩展到可配置的 0-7（`--from <n>`），但**只改了「前进」逻辑，漏改「回退」逻辑**。这暴露两个问题：

1. **回退下界硬编码 `"4"`**：5-test/6-review/7-integration 三个 prompt 的失败回退 jq 仍是 `current_phase = "4"`，忽略 `start_phase`。`--from 0` 启动时，用户无法回退到 0-3 规划阶段。
2. **规划层根因无处可退**：5/6/7 失败的根因不一定在实现层（4-dev）——可能是 AC 错误（回 1）、架构决策缺陷（回 2）、任务拆解遗漏（回 3）。当前回退选项只有「回退到 4-dev」，规划层失败无法处理。

这是 `goal-pipeline-phase0` 的**设计完整性缺口**，性质与已修复的 TD-003（入场 jq 漏 start_phase）同类，但更深——前进和回退是 pipeline 的两面对称设计，扩展一边必须同步另一边。

## What（做什么）

采用**方案 C（智能回退）+ B（多级可选）结合**：

1. **失败分类表**（prompt 内嵌）：在 5/6/7 的 pipeline rollback 段，新增一张「失败现象 → 建议回退阶段」映射表，让 AI 根据失败类型智能建议回退目标，而非一律回 4。
2. **动态回退目标列表**：回退选项不再硬编码「回退到 4-dev」，而是根据 `start_phase` 到当前阶段动态生成可回退阶段列表（`--from 4` 时仅 4 可退，`--from 0` 时 0-4 都可退）。
3. **回退 jq 通用化**：把 `current_phase = "4" | phases_done -= ["5"]` 这种硬编码，改为接受目标阶段的通用形式（回退到 N → `current_phase = "<N>"` + 移除 N 及之后的已完成阶段）。
4. **向后兼容**：`--from 4`（默认）场景下，失败分类表的建议仍是「回 4」（最常见根因），行为与现状一致。

## 范围排除（这次不做）

- **不做程序化失败分类器**（不写脚本读测试输出自动判断失败类型）——由 prompt 驱动 AI 按失败分类表建议，保持 markdown 工程一致性
- **不改 `--from 4` 的默认回退行为**（`--from 4` 仍默认建议回 4，完全向后兼容）
- **不引入「跳过阶段」的新语义**（回退总是退到某个已完成阶段，不跳过未执行阶段）
- **不改变 toll-gate 模型本身**（toll-gate 暂停-确认机制不变，只扩展失败后的回退选项）
- **不动 fix-pipeline-rollback 已建立的 AC-10 rollback 基础**（在其上扩展，不重写）
- **不改 4-dev.md 的 rollback 逻辑**（4-dev 是回退终点，无下游回退）

## 验收线（粗粒度，不是 AC）

1. 5/6/7 三个 prompt 的 pipeline rollback 段含「失败分类表」+「动态回退目标列表」
2. 回退 jq 通用化（接受目标阶段参数，不再硬编码 `"4"`）
3. `--from 4` 场景回退行为不变（向后兼容）
4. `--from 0` 场景失败时，AI 能根据失败类型建议回退到 0/1/2/3/4
5. 新增测试覆盖回退 jq 的通用形式

## 风险与未知

- **风险**：失败分类表可能不全面（漏掉某种失败类型）→ 缓解：覆盖最常见 4 类（代码 bug / AC 错误 / 架构缺陷 / 任务遗漏），加「其他 → 默认回 4」兜底
- **风险**：动态回退目标生成逻辑写进 prompt，AI 执行时可能算错可回退阶段 → 缓解：给出明确的 jq 表达式模板（从 start_phase 到 current_phase 的范围）
- **未知**：回退到 0-3 后，规划阶段的 prompt（0-change 等）是否需要感知「这是回退来的」→ 初步判断不需要（重新走 0-change 流程即可，toll-gate 会再次确认）
