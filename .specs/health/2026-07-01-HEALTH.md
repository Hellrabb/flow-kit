## 🔴 Critical-1 · `package-flow-kit.sh:581-587` 孤儿 `fi` 语法错误

**症状（铁证）**：

```
$ bash -n package-flow-kit.sh
package-flow-kit.sh: 行 586: 未预期的记号 "fi" 附近有语法错误
package-flow-kit.sh: 行 586: `  fi'
```

**根因**：文件末尾（banner 打包完成输出之后）挂着一段 `validate_staging_coverage()` 函数的**残留碎片**：

```bash
# 行 581-587（应整段删除）
# ═══...
# validate_staging_coverage() — 校验 Part A~G staging 指令覆盖完整性
    echo ""
    echo "   ✅ 校验通过：所有文件均被 Part A~G 覆盖。"
    exit 0
  fi        ← 孤儿 fi（无匹配的 if）
}           ← 孤儿 }（无匹配的函数体开头）
```

这是顶部完整函数定义（行 19-139）的**中段尾巴被重复粘贴**到文件末尾。来源是本周某个 package commit 的编辑失误（commit `720246e` "修复 --validate 两处 bug" 触及过该文件；基线 `b286c22` 语法 OK → **本周引入的回归**）。

**影响**（分场景）：

| 调用方式 | 行为 | 严重度 |
|---|---|---|
| `bash -n` / shellcheck / CI lint | ❌ 立即失败 | 阻断静态检查 |
| `./package-flow-kit.sh --validate` | ✅ 能跑（`exit $?` 在解析到孤儿 `fi` 之前触发） | 偶然可用 |
| `./package-flow-kit.sh`（正常打包） | ⚠️ 打包流程跑完、tar 生成，但执行到末尾触发语法错误，**退出码非 0**；并打印假的 `✅ 校验通过` | 阻断 `&& publish` 类自动化 + 误导 |
| `./package-flow-kit.sh && deploy` | ❌ 因退出码非 0，`deploy` 不执行 | **打包产物虽生成但下游被阻断** |

**修复**：删除 `package-flow-kit.sh` 第 581-587 行（保留第 579 行 banner 结尾 `╝"` + 第 580 空行作为文件结尾即可）。无功能损失 —— 顶部 19-139 行的 `validate_staging_coverage()` 是完整且正确的定义。

## 🟢 Minor-1 · `flow-kit-resume.sh:95` jq 错误吞咽

```bash
corr_count=$(jq -r '.violations | length // 0' "$compliance_correction_file" 2>/dev/null)
```
