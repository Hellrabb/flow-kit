# ADR-001: 弱模型鲁棒性哲学 — Protect the Weakest

- **状态**: accepted
- **日期**: 2026-06-25
- **关联 change**: `weak-model-robustness`（`@.specs/weak-model-robustness/DESIGN.md` D5）

---

## Context（背景与触发）

flow-kit 的规则（`RULES.md`/`SYSTEM.md`）与各阶段 prompt 原本按**强模型**（Claude 级，能稳定自觉遵守指令、低幻觉）设计，大量依赖模型"自觉"：自觉反问、自觉读 RULES、自觉不幻觉、自觉守 checkpoint。

当换用能力略弱、幻觉偏多的模型（实测：`minimax-m2.7` / `qwen3.6-35b-a3b` / `deepseek-v4-pro`）时，"靠自觉"的假设全面失效，出现全套失败模式：跳反问、幻觉 API/字段、不读 RULES、范围漂移、中途漂移。

需要决定一个**哲学层面的方向**：flow-kit 的规则/prompt 该按什么基准写？可选方向有三：

1. **protect the weakest**：默认按最弱模型能扛住的标准写，所有人开局受保护。
2. **运行时自动探测 + 双轨**：探测当前模型强弱，自动切换轻量/严格流程。
3. **维持现状（按强模型写）**：弱模型用户自己想办法。

## Decision（决策）

采用 **protect the weakest**，并加两项关键限定：

1. **默认全含加严**：`RULES`/prompt 按"最弱模型能扛住"的标准编写，所有人开局即受保护——**不需要弱模型主动 opt-in**。
2. **降级才 opt-out**：强模型用户通过显式声明（`model_tier: strong`，v2/L4 实现）触发轻量模式，跳过冗余检查。选择权在**人**（用户知道自己用什么模型），不在模型。
3. **结构刚性限定**：加严只加**结构刚性护栏**（禁跳反问、填空模板、证据链、关键节点 checkpoint、阶段入场锚定）——这些强模型本来就该做、不啰嗦；**不加"重复唠叨"**（每步复述 goal、每操作 checkpoint、冗余自检），因为啰嗦会反噬强模型、甚至增加幻觉（长上下文 / 注意力分散 / 指令淹没）。由 AC-7（强模型 token/turn 增量 < 20%）强制约束。

**否决**"运行时模型能力自动探测"（方向 2）：弱模型会幻觉自己很强，自报不可靠；跑小测试探测又费 token。唯一可靠的 tier 信息来自**人**的显式声明，而那属于 L4（v2），不属本次。

**否决**"维持现状"（方向 3）：与本次 change 的存在意义矛盾。

## Consequences（后果）

**正面**：
- 弱模型获得默认保护，无需任何配置。
- 风险不对称成立（在"结构刚性"限定下）：弱模型缺约束崩溃的代价 ≫ 强模型多几条结构约束的代价。
- 加固内容（R3/R6/R7 增强 + 各 prompt gate）对所有使用者一致，无双源不一致风险。

**负面 / 代价**：
- 强模型多几条结构约束（轻微啰嗦），由 AC-7 限定在 < 20% 增量内。
- "弱模型"边界仍模糊（多弱算弱），需 v2 / TEST 阶段定精确基线。
- 完整的 opt-out（L4）留 v2，本次强模型暂无法主动降级——但"结构刚性"设计已使其几乎无感。

**未来推翻条件**（此 ADR 可重新评估的触发点）：
- 弱模型能力普遍提升到"能稳定自觉遵守"水平 → 可放松默认加严。
- L4 opt-out 机制成熟后，可重新评估"默认偏严 vs 默认偏轻"的权衡。
- 出现可靠的运行时 tier 探测手段 → 可重新考虑双轨。
